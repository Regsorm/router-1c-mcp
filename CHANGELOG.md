# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/), версии по [SemVer](https://semver.org/lang/ru/).

Публичная история проекта начинается с версии 0.8.0.

## [0.8.0] — 2026-10-28 — состав инструментов по базам

### Добавлено

- **Инструкция по установке.** Отдельный файл `INSTALL.md`: скачивание архива
  из Releases или своя сборка, файл баз, переменные окружения, запуск, проверка
  `/health`, подключение MCP-клиента к `/mcp`. В README — ссылка на инструкцию.
- **Настройка числа повторов опроса.** `MCP_RETRY_ATTEMPTS` (переменная) или
  поле `retry_attempts` в обёрнутом файле баз; переменная главнее, `0` —
  не повторять совсем. Не задано — пять попыток.
- **Опрос всех баз при старте.** Вместо снимка `tools/list` с первой живой базы
  каждая база опрашивается параллельно (`initialize` → версия расширения, затем
  `tools/list`) в отдельной задаче; роутер дожидается ответа всех баз.
- **Матрица «инструмент → базы».** У каждого инструмента в параметре `base` свой
  `enum`: только те базы, которые этот инструмент действительно отдают. Остальные
  параметры и `required` инструмента сохраняются.
- **Файл состава `tools.json`.** Поля `_generated` (UTC, ISO-8601), `common`
  (инструменты, которые есть на всех ответивших базах) и `separate` (инструменты
  конкретной базы вне `common`). Перезаписывается при каждом старте. Путь —
  `MCP_TOOLS_FILE`, иначе `tools.json` рядом с файлом баз, иначе в рабочем
  каталоге.
- **Выбор схемы по версии расширения.** Если одно имя пришло с нескольких баз с
  разными схемами, берётся определение с самой старой версией расширения — чтобы
  вызов проходил на всех базах, где инструмент есть. Расхождение пишется в журнал.
- **Фоновый повтор с ограничением.** Базы, не ответившие при старте,
  опрашиваются раз в две минуты, но не бесконечно: по умолчанию пять попыток
  (десять минут), затем цикл останавливается; когда ответили все базы — сразу.
  Восстановленная база добавляется в состав, файл перезаписывается, инструменты
  публикуются без перезапуска процесса.
- **Сборка под Linux.** `cargo zigbuild` с целью `x86_64-unknown-linux-gnu.2.17`
  (требует glibc не новее 2.17) и `x86_64-unknown-linux-musl` (статический
  бинарь).

### Изменено

- **Белый список инструментов переехал в файл состава.** `tools_enabled` теперь
  живёт в `tools.json` (секция читается при старте и сохраняется при каждой
  перезаписи, в том числе фоновой). Порядок ключей файла строгий: `_generated`,
  `tools_enabled`, `common`, `separate`. Файл баз стал только про подключения:
  поле `tools_enabled` в нём больше не читается и игнорируется, если осталось.
  Приоритет прежний — непустая `MCP_TOOLS_ENABLED` главнее файла, значение
  переменной в файл не пишется.
- **Проверка матрицы «инструмент → базы» на вызове.** Вызов инструмента с базой,
  которая его не предоставляет, отбивается роутером до форвардинга: результат с
  `isError=true` и русским текстом (`Инструмент 'X' недоступен для базы 'Y'` или
  `Инструмент 'X' отсутствует в составе инструментов`). Запрос в базу не уходит,
  порядок проверок — белый список, затем матрица, затем форвардинг.
- Пакет и бинарь переименованы в `router-1c-mcp`, имя MCP-сервера в `ServerInfo`
  — `router-1c-mcp`.
- Версия расширения сравнивается по числовому ядру: суффикс сборки (`1.8.2-lite`)
  больше не делает живую базу неответившей.

### Удалено

- **Собственный ключ доступа к 1С.** Заголовок `X-MCP-Key` и переменная с
  ключом доступа больше не читаются и не отправляются: открытое расширение
  Харина их не использует, авторизация к базе — только Basic Auth
  (`username`/`password` из списка баз). Если переменная осталась в окружении,
  она игнорируется; в подсказках `export_artifact` и `import_artifact` ключ не
  упоминается.

### Совместимость

- Список инструментов, который видит клиент, изменился: инструмент предлагается
  только тем базам, где он есть. Новый список клиент получит после
  переподключения — `listChanged` не заявляется и уведомлений нет.
- Имя бинаря изменилось. Если внешние скрипты запускали его по старому имени,
  их нужно поправить.
