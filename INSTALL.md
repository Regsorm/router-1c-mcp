# Установка router-1c-mcp

Кратко: скачать архив, описать базы, задать три переменные, запустить,
подключить MCP-клиент. Устройство роутера и формат файла состава — в
[README.md](README.md), изменения — в [CHANGELOG.md](CHANGELOG.md).

## Что нужно заранее

1. В базе 1С установлено расширение `MCP_Сервер` и опубликован его
   HTTP-сервис — см. раздел «Расширение 1С» в [README.md](README.md).
   Инструменты живут в расширении: без него роутеру нечего отдавать.
2. Пользователь 1С с доступом к этому HTTP-сервису (логин и пароль для
   Basic Auth).
3. Свободный порт на машине, где будет работать роутер.

## 1. Возьмите бинарь

- Windows: `router-1c-mcp-windows-x64.zip` из
  [Releases](https://github.com/Regsorm/router-1c-mcp/releases).
- Linux: `router-1c-mcp-linux-x64.tar.gz` оттуда же (требует glibc не новее
  2.17).
- Своя сборка: `cargo build --release` или `cargo zigbuild` — см. раздел
  «Для разработки» в [README.md](README.md#для-разработки).

Распакуйте архив в отдельный каталог, например `C:\Tools\router-1c-mcp` или
`/opt/router-1c-mcp`: рядом будут лежать настройки, файл состава и журнал.

## 2. Опишите базы в `bases.json`

```json
[
  {
    "name": "base-a",
    "url": "http://1c-host/base-a",
    "username": "mcp-user",
    "service_root": "mcp",
    "max_concurrent": 4
  }
]
```

Пароль в примере не показан: если публикация закрыта Basic Auth, добавьте рядом
с `username` поле `password` и укажите в нём пароль.

| Поле | Обязательно | Смысл |
| --- | --- | --- |
| `name` | да | имя базы — значение параметра `base` в вызове инструмента |
| `url` | да | корень публикации, без `/hs/...` |
| `username`, `password` | нет | Basic Auth к публикации |
| `service_root` | нет, по умолчанию `mcp` | корень HTTP-сервиса: вызов уходит на `/hs/<service_root>/rpc` |
| `max_concurrent` | нет | потолок одновременных запросов к этой базе, лишние ждут в очереди |

Баз может быть любое количество — в одном процессе обслуживаются все.

## 3. Задайте переменные окружения

```
MCP_HOST=127.0.0.1
MCP_PORT=8010
MCP_ONEC_BASES_FILE=C:\Tools\router-1c-mcp\bases.json
```

Если переменные не заданы, роутер слушает `127.0.0.1:8010` — это значения
по умолчанию. Файла конфигурации нет, вся настройка — переменными. Остальные
переменные (`MCP_TOOLS_FILE`, `MCP_TOOLS_ENABLED`, `MCP_RETRY_ATTEMPTS`,
`MCP_DOWNLOAD_PUBLIC_URL`) — в [.env.example](.env.example).

## 4. Запустите

```
router-1c-mcp.exe          # Windows
./router-1c-mcp            # Linux
```

Фоновый запуск на Linux:

```
(setsid ./router-1c-mcp >> run.log 2>&1 </dev/null &)
```

Автозапуска в комплекте нет: службу или systemd-юнит настраивают отдельно.

## 5. Проверьте запуск

```
curl http://127.0.0.1:8010/health
{"bases":1,"service":"router-1c-mcp","status":"ok","version":"<версия>"}
```

- `bases` — сколько баз ответило при старте;
- рядом с файлом баз появился `tools.json` — состав инструментов по базам;
- база, не ответившая при старте, опрашивается повторно каждые две минуты, но
  не бесконечно: по умолчанию пять попыток (`MCP_RETRY_ATTEMPTS`), затем цикл
  останавливается; перезапуск не нужен.

Инструменты можно посмотреть и без MCP-клиента:

```
curl -s -X POST http://127.0.0.1:8010/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
```

## 6. Подключите MCP-клиент

Адрес `http://127.0.0.1:8010/mcp`, транспорт StreamableHTTP, stateless —
после перезапуска роутера клиенту не нужно новое рукопожатие. Пример для
клиента, читающего `.mcp.json`:

```json
{
  "mcpServers": {
    "router-1c-mcp": { "type": "http", "url": "http://127.0.0.1:8010/mcp" }
  }
}
```

В каждом вызове инструмента обязателен параметр `base` — имя базы из
`bases.json`.

## Если что-то не так

| Симптом | Что проверить |
| --- | --- |
| `Список баз пуст` | задан ли `MCP_ONEC_BASES_FILE` (или `MCP_ONEC_BASES`) и читается ли файл |
| `bases` в `/health` меньше ожидаемого | проверьте расширение и публикацию базы, логин и пароль (иначе 401), сеть до базы |
| инструмент не появился в выдаче | белый список (`MCP_TOOLS_ENABLED` или `tools_enabled` в `tools.json`) и ответила ли база |
| `Инструмент 'X' недоступен для базы 'Y'` | у этой базы нет такого инструмента — матрица работает как задумано |
| порт занят | смените `MCP_PORT` |

Белый список и порядок ключей в файле состава описаны в
[README.md](README.md#белый-список-инструментов).
